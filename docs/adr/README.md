# Architecture decisions

Each decision was made by the human on 2026-11-14. These are short records so agents don't reopen them. To change one, add a new ADR that supersedes it.

| ADR | Decision | Status | Why | Consequence |
|---|---|---|---|---|
| 001 | Agents chat through **NEAR AI Cloud** (`cloud-api.near.ai/v1`, OpenAI-compatible), default model a verifiable TEE model | Accepted | Private, verifiable inference fits a NEAR hackathon. Upstream chat is already OpenAI-compatible, so it's a small swap | Needs prepaid NEAR AI credits. Spike the model id, latency and reasoning toggle first |
| 002 | Payments go through a **small NEAR contract** (`spot_pay`), not a plain transfer | Accepted | Deeper NEAR use: an on-chain record per quote, a fee split and events | About 4–6 extra hours. Contract source in `contract/src/lib.rs` |
| 003 | Users sign with a **real wallet** through a NEAR wallet connector (wallet selector or NEAR Connect, decided in the spike) | Accepted | Honest, non-custodial and standard | The phone needs a testnet wallet. The redirect flow must return to the app |
| 004 | Contract in **Rust** (`near-sdk-rs` + `cargo-near`), built in **WSL Ubuntu** | Accepted | The best-maintained NEAR path. Windows has no Rust installed, and WSL avoids the MSVC toolchain | About 20 minutes of setup. Steps in `docs/SETUP.md` |
| 005 | The contract **forwards funds instantly**: creator and treasury are paid in the same call, and nothing is held | Accepted | Less state and less risk | A failed transfer to a missing account leaves funds in the contract, so the quote checks the account exists first |
| 006 | **5% platform fee** (500 bps, maximum 2000), integer floor in yocto | Accepted | Shows a business model | The fee is rounded down. Tests cover a 1-yocto payment |
| 007 | **Hosted Supabase** (free tier), anonymous auth | Accepted | The phone can reach it outdoors for the demo | The human creates the project and sets secrets |
| 008 | **Mobile web app** with `<model-viewer>` WebXR/Scene Viewer AR, not native Android/ARCore | Accepted | Cuts native build and test effort by about 80%, given the deadline | AR quality is limited to what WebXR offers. Android Chrome is the target, and iOS is best effort |
| 009 | **Guided session with escrow** (supersedes 005 for the main flow): the free greeting and first question happen on arrival (geofence auto-invoke). To continue, the tourist starts a paid session: `start_session` holds the deposit in the contract; `release` pays the guide (95%) and the treasury (5%). Release happens when the tourist ends the session, or anyone may call it 30 min after start. Old `pay` stays for compatibility | Accepted (human, 2026-11-14) | The tourist pays for service delivered, so the guide is paid only after the session | New contract account `spotpayv2.sweetfrog-treasury.testnet`, because the old state layout can't be upgraded in place. Refunds and disputes are future work |
| 010 | **Focus: heritage guides at Shaniwar Wada**, with a **Virtual visit mode**: freely licensed photos along a real route, a simulated GPS walk, and the same geofence auto-invoke. Shops and vendors are mentioned as the next market only | Accepted (human, 2026-11-14) | Judges aren't in Pune, and the walk is reproducible anywhere. Only the camera and GPS are simulated, and the UI labels it | Home spots are no longer in the demo |
| 011 | **Guide avatar = TalkingHead sample `brunette.glb` (Ready Player Me, CC BY-NC 4.0); layout L3 "portrait bubble"** (the monument fills the screen; the guide talks from a portrait window with live captions) | Accepted (human, 2026-11-14, NC licence risk acknowledged) | Most expressive face and best-tuned lip-sync for the time left | Credited as CC BY-NC 4.0 in the README, BASELINE and About screen. Replace it with a CC0 model before any commercial use |
